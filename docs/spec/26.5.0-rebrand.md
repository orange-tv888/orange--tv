# 需求单：品牌归位与许可补齐

- id：`26.5.0-rebrand`
- 档位：L
- 版本：`26.5.0`
- 提出：2026-11-04
- 拍板：2026-11-04 用户决定 —— namespace 一并改为 `app.orange.tv`；署名用 `JC Aerial`

## 一、目标（PM）

一句话：**让这台电视上的 Orange 在界外（README、官网、代码、安装包）也完整地叫 Orange，同时把 MIT 要求的署名与许可全文补齐，而不是现在这样「品牌是上游的、署名却没有」。**

法律前提（2026-11-04 核实）：仓库根 `LICENSE` 为 MIT，`Copyright (c) 2026 pengchujin`。MIT 明确允许修改、改名、闭源、商用，**不要求**保留产品名或商标；唯一义务是「在所有副本或实质部分中保留版权声明与许可声明」。因此：

- 删上游品牌 → 合法；
- 删上游署名 → 违约；
- 二者必须同时做，只做前者会把「合法改名」变成「违反许可条件」。

## 二、使用场景（PM）

1. 用户装好后在电视上翻到「关于」，能读到 MIT 全文、上游版权行、本项目为衍生作品的说明——这是唯一让 MIT 义务可被履行的地方，现在完全不存在。
2. 用户在电脑上看仓库首页，看到的是 Orange 的介绍和自己的下载路径，而不是上游作者的项目页与他的下载站。
3. 维护者在 adb 里敲命令时，包名与组件名一致（`app.orange.tv/app.orange.tv.MainActivity`），不必记两套。
4. 将来若把仓库转给他人或申请商标，代码、文档、安装包里没有第二套品牌名的历史包袱。

## 三、不做什么（PM）

- **不动签名证书**：`CN=JC Aerial` 保持。换证书 = 老设备永远无法覆盖安装。证书是签名标识，装完不可见，保留不构成展示性使用。
- **不删上游 issue 链接**：`github.com/pengchujin/aerial-tv/issues/NNN` 是他人讨论存档，改了全 404。可加「上游记录」措辞，链接本身保留。
- **不删 `FONT-LICENSE-OFL.txt`**：Inter 字体走 OFL，有独立义务，不随品牌清理一起删。
- **不改 `applicationId`**（`app.orange.tv`）：改了就是另一个应用，已装设备收不到更新。
- **不重新生成密钥、不动版本号语义**：本次发 26.5.0。
- **不把 `aerial` 当品牌名以外的词一起替换**：`aerial films`（航拍影片）、`AerialSet`（影片集合）是功能描述与类名，按第四段判据分别处理。
- **不做对外发布**：不建 Release、不宣传。README 指向仓库内路径，不指向任何下载站。

## 五、方案（CTO，G1 填）

- 改动面：见下方「改动清单」
- 关键取舍：
  - **namespace 改、applicationId 不改**。namespace 只决定生成代码的包名（R、BuildConfig）与源码 import 路径，不参与安装识别；因此签名校验、覆盖安装、更新通道全部不受影响。代价是组件名变化 → 已装设备的默认桌面绑定失效一次，用 `tools/install.sh` 重跑即可。
  - **类名统一去掉 Aerial**。`Aerial`（一部影片）/`AerialSet`/`AerialStream`/`AerialQuality`/`AerialFormats` 改为 `Film`/`FilmSet`/`FilmStream`/`FilmQuality`/`FilmFormats`——「航拍影片」是领域词，用 Film 比套一层 Orange 更贴切；`AerialSettings`/`AerialDream`（指代本应用的）改为 `OrangeSettings`/`OrangeDream`。文件随之 `git mv`，`assets/aerials.json` 改 `films.json`。
  - **主题名 `Theme.Aerial` 改名**，但它被 manifest 的 `android:theme` 引用，必须同步，且没有任何外部依赖引用它——风险低。
- 风险：编译期集中暴露（108 个文件 import 全变），漏改会在编译时报 unresolved reference，不会静默坏。真机侧唯一风险是 HOME 绑定，有现成脚本回滚。
- 回滚：`git revert` 本单提交；真机侧 `TV=192.168.1.8 tools/restore.sh`。
- 测试点：组件名、HOME 解析结果、关于页可读性、更新通道仍通。

### 这一轮新发现的一个真 bug

`tools/install.sh` 的 `guard_bound()` 原本是
`grep -q -E "label=(Aerial|app\.orchard\.tv)"`。真机上 `dumpsys accessibility` 打出来的是
`label=app.orange.tv.guard.Ho…`（label 就是类名），两个分支**都匹配不上**，于是脚本永远判定守护没绑定，每次安装都白跑一遍开守护的流程。已改为 `label=(Orange|app\.orange\.tv)`。
第一轮没发现它，是因为这处包名写成转义形式 `app\.orchard\.tv`，`grep "app\.orchard"` 匹配不到。

### 第三轮：原本打算留下的四样，也一并改了（用户 2026-11-04 12:13 拍板）

前一版把下面四样列为「故意不动」，理由是它们牵着已装设备上的状态。用户的要求是「4 样没有动一并动了，装机实测，没问题再推送发版」，并说明「目前老设备就一台，就是我们这台电视」——所以每一处都按「改名 + 旧值兼容」处理，实测在新包上重装验证。

| 东西 | 改成了什么 | 旧设备上的值怎么办 |
|---|---|---|
| `dream/AerialDream` | `dream/OrangeDream`（组件名随之变为 `app.orange.tv/app.orange.tv.dream.OrangeDream`） | 系统 `screensaver_components` 里存的旧组件名会失效，**屏保需要重设一次**；`tools/install.sh` 本来就会在每次安装时重写这一行，跑一遍即恢复 |
| `aerial_vt_home_pkg`（global key） | `orange_vt_home_pkg` | `install.sh` 写新键并删旧键；`restore.sh` 先读新键、读不到再读旧键，海信电视的原桌面不会丢 |
| `Account("Aerial", …)` | 新建账户名 `Orange` | 账户按 type 查，旧名账户会被直接复用，不需要迁移；系统设置里那一栏可能仍显示旧名，不影响任何行为 |
| `Aerial`/`AerialSet`/`AerialStream`/`AerialQuality`/`AerialFormats`/`Aerials` | `Film`/`FilmSet`/`FilmStream`/`FilmQuality`/`FilmFormats`/`Films` | 纯代码标识符，不影响设备 |

顺带一并改掉的持久化名字，都带迁移或兼容：

- `SharedPreferences "aerial_set"` → `"orange_set"`：`FilmSet.prefs()` 首次使用时把整个旧文件逐键复制过来，正在播的那部片子和当天的选择都还在。
- `SharedPreferences "aerial"`（亮度）→ `"orange"`：`Brightness.storedLevel()` 读不到新值时读旧值并写回新键。
- prefs 键 `"aerial_quality"` → `"film_quality"`：读取时先新键、后旧键，已选的画质不会掉回 Auto。
- PIN 盐 `"aerial:$pin"` → `"orange:$pin"`：`unlock()` 两个盐都试一次，**已经设过 PIN 的电视不会把自己锁在外面**。
- 缓存目录 `cacheDir/aerials` → `films`、日志文件 `aerial-diag.log` → `orange-diag.log`、更新临时文件 `aerial.apk`/`aerial.dm` → `orange.*`：都是可重建的，直接换名。

仍然保留的 `aerial` 只有三种，都不是品牌：

- `aerial films` / `aerial wallpaper` 这类英文普通名词（航拍），以及资源名 `ss_aerial`；
- `OrangeSettings` 里音效枚举的 key `"aerial"`；
- 上面那些迁移代码里写明的旧名字（`PREFS_BEFORE_RENAME`、旧盐、旧键），不写就迁不动。
