# 需求单：新图标（橙子标记）与开机音

> PM 写前三段，CTO 写「方案」段。G1 过门后不再改前三段。

- id：`26.6.0-icon-chime`
- 档位：M
- 版本：26.6.0
- 提出：2026-11-04

## 一、目标（PM）

两件事，都指向同一件事：**这台电视开机的时候，看起来是 Orange 而不是一个不明应用。**

1. 应用图标换成用户给的那张：浅灰底、橙色圆环、顶部一小段深灰的梗（读起来像一只橙子，不是字母 O）。
2. 开机时有一声「咚」，类似 iPhone 开机的那种低沉打击音。

## 二、使用场景（PM）

1. 电视的应用列表里，现在的图标是橙渐变底 + 一道白色弧线。弧度太抽象，看不出是橙子，和名字对不上。
2. 电视开机 → 厂商 logo → 桌面出现，中间是**完全无声**的。用户想要一个「开始」的信号，而不是静默跳进桌面。

## 三、不做什么（PM）

- **不动系统的开机动画。** `bootanimation.zip` 在 `/system/media`，要 root 或系统签名才写得进去；而且 Android 的开机动画本身不支持音频。所以「开机音」只能由 Orange 自己在**桌面起来的时刻**发出，做不到厂商动画那一段。这一点必须先说清楚，否则做出来不是想象的样子。
- **不采样任何设备的原始开机音。** 苹果那声是它的；这里用正弦谐波合成一个同类质感的音，版权归自己。
- 不改「界面音效」的三档设置（关 / 电视 / Orange）的结构。开机音跟随「关」——声音全关掉的电视，开机也不该说话。
- 不动 TV banner 的橙色渐变底色（只是把里面的图形换成新标记），横幅在应用列表里要够醒目。

## 四、验收判据（PM，每条必须可验证）

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 图标在方形、圆角方形、圆形三种裁切下，圆环与顶部梗都不被切 | 按 108dp 画布模拟三种遮罩，肉眼看梗尖完整 |
| 2 | 老系统（5.x–7.x，读不到 adaptive icon）看到的是同一张图 | `mipmap-*/ic_launcher.png` 与新标记同源渲染，不是两套设计 |
| 3 | 应用列表里的横幅仍是橙底白字，图形与图标一致 | 装机看 TV 应用列表 |

## 五、方案（CTO，G1 填）

### 图标

用户给的是 1024×1024 位图。**不直接缩放使用**，按它重建为矢量：位图在 48dp（mdpi）与 192dp（xxxhdpi）之间缩放会糊，而且 adaptive icon 必须是矢量或分套位图。

从原图量出的几何（全部换算到 108dp 画布）：

| 量 | 原图（1024） | 108dp 画布 |
|---|---|---|
| 环心 | (506, 578) | (54.07, 58.52) |
| 环外径 / 内径 | 692 / 490 | 24.22 / 17.15 |
| 环厚 | 101 | 7.07 |
| 梗宽 | 54 | 3.78 |
| 梗：竖笔 | x 509，y 130→237 | x 54.28，y 27.16→34.65 |
| 梗：横钩 | 从竖笔中部向右弯到 x 645 | 两段三次贝塞尔 |

配色：环 `#FEB05D`、梗 `#5A5957`、底 `#EEEDEB`（都是从原图采样的，不是估的）。

梗的形状是「r」：竖笔顶端高出横钩一截，横钩从竖笔**中部**伸出。这一点靠两次扫描确认过——按 y 扫得竖笔在 x 482–536，按 x 扫得横钩中心线在 y 141–161 之间起伏，如果按「直角拐弯」画，横钩会长在竖笔顶端，和原图差一截。

**安全区**：整个标记（含梗尖）在 108dp 画布上的最远点是 35.2dp，圆形裁切半径是 36dp —— 刚好不被切，这是选 `s = 0.070` 的原因。放大到 0.078 能让主体大 11%，但梗尖会被削平。

落地：
- `res/drawable/ic_launcher_background.xml`：纯色 `#EEEDEB`（原来是橙渐变）
- `res/drawable/ic_launcher_foreground.xml`：环（两段 arc 拼整圆）+ 梗（两条 stroke path）
- `res/mipmap-*/ic_launcher.png`：5 个尺寸，从同一组数字渲染（圆角 22%）
- `docs/brand/icon.svg`、`docs/brand/icon.png`、`site/favicon.svg`：同步
- `res/drawable-{xhdpi,xxhdpi}/banner.png`：橙渐变底 + 白色标记 + 白字，标记高 48dp、文字从 104dp 起

### 为什么改渲染脚本

`tools/render-brand.py` 原来用 `rsvg-convert` 从 `icon.svg` 渲染 mipmap。这台机器上 **rsvg-convert 没装**，也就是说这个脚本在改设计的那一刻是跑不起来的。改成纯 Pillow 按同一组常量绘制：不引入依赖，也保证「矢量源」和「位图产物」用的是同一批数字（常量写在脚本顶上，注释指向 `icon.svg`）。

### 开机音

- 音源：`tools/make-boot-sound.py` 生成，`res/raw/boot.wav`（单声道 48 kHz 16 bit，1.2 s）。做法是「一击金属声」：一个基频加一组非谐波分音，各分音按不同速率衰减；起音瞬间频率略高再落回，这一下是「有实体被敲」和「电子哔声」的区别。候选三档（`warm` 196 Hz / `deep` 110 Hz / `bell` 330 Hz）在桌面，选中的是 `warm` + 一段短房间反射。
- 播放：`Sounds.boot()`，**独立 SoundPool**。不复用 `ownPool` 是因为它只在「界面音效 = Orange」时才加载，而开机音在两档音效下都要响。用 `USAGE_MEDIA` 而不是按键音那套 sonification —— 它跟随电视平时的音量，静音就是静音。
- 加载异步：`SoundPool.load` 返回时样本通常还没解完，直接 `play` 会**刚好在最需要它的那一次**没声音。所以用 `setOnLoadCompleteListener` 在加载完成回调里播。
- 时机：`MainActivity.startWork()` 里判断 `SystemClock.elapsedRealtime() < 3 分钟`。刚开机时进程就是这个时间窗内起来的；按 HOME 回来、切应用回来，进程已经跑了几小时，`elapsedRealtime` 早超出窗口，自然不响。再加一个进程内静态标记兜底（`startWork` 每次回桌面都会走）。
- 延迟 700 ms：开机后音频服务要起来，桌面也要先画出来，声音才和画面对上。

### 风险

- `USAGE_MEDIA` + 电视媒体音量为 0 时无声。这是对的，但用户可能以为是坏了。
- 冷启动判定依赖 `elapsedRealtime`。电视如果是「休眠唤醒」而不是真重启，时间窗口早就过了，不会响 —— 符合预期。
- adaptive icon 改成浅底之后，在深色应用列表里对比度比原来的橙渐变低。只能在真机看效果，必要时把底色改成纯白。
