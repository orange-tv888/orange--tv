# Orange 工作流程

流程只为一件事服务：**把返工和误判挡在发版之前**。除此之外不加任何环节。

## 角色

四个角色，人和 AI 混着当。分角色的标准不是"谁在说话"，而是**产物由谁签**。

| 角色 | 谁 | 只负责 | 交付物 | 不许做 |
|---|---|---|---|---|
| 产品（PM） | 用户，AI 代笔 | 需求梳理、方案取舍、验收口径 | `docs/spec/<id>.md` | 不写代码，不承诺日期 |
| 技术（CTO） | AI | 技术方案、实现、自测 | 同一份 spec 的「方案」段 + 代码 | 不许改验收判据 |
| 测试（QA） | AI 换视角 + 用户验手感 | 按判据独立验、回归、找漏 | `docs/qa/<id>.md` | 不许改代码，发现 bug 回给技术 |
| 发布（Release） | AI | 版本号、打包、上线、归档 | `release.sh` 产物 + `update/version.json` | 不许跳过 QA |

用户的不可替代之处：**PM 的拍板**和**QA 的手感**。电视上"按起来顺不顺""看着像不像"只有人能给，AI 只能给数字。

## 门禁

六个门，每道门有判据，不过门不进下一段。判据写成能验证的形式，能量化就量化。

| 门 | 谁签 | 过门判据 |
|---|---|---|
| G0 立项 | PM | 写清四件事：目标、使用场景、**不做什么**、验收判据（每条可验证） |
| G1 方案 | PM + CTO | 改动面清单（哪些文件/模块）、风险、回滚办法、测试点。PM 点头才准写代码 |
| G2 自测 | CTO | 编译过；自己先按验收判据走一遍，把结果填进 spec |
| G3 验收 | QA | 逐条判据过，每条附证据：截图 / 日志行 / 像素差 / 时间差。缺证据 = 没过 |
| G4 发版 | Release | 版本号符合 `26.Y.P`、说明 ≤4 条、三份 APK 同哈希、中转能读到 |
| G5 复盘 | 全体 | 发版后 24 小时内写完 `docs/retro/<version>.md`，至少一条改进项落到脚本或门禁 |

## 分档

全流程套在"改一个文案"上没人执行。按改动大小分三档，**档位决定要几张单子**。

| 档 | 什么算 | 要做什么 | 分支 |
|---|---|---|---|
| **L 大改** | 动架构、动开机链路、换视觉语言、跨 5 个以上文件 | 全流程 G0–G5，方案单独评审，复盘完整 | `feat/<id>` + `--no-ff` 合入 |
| **M 功能** | 新功能、明显的行为变化、改版式 | G0 需求单（可以短）+ G3 验收 + 复盘三行 | `feat/<id>` |
| **S 小修** | 文案、1px、错字、参数微调 | 免文档，但 G3 必须有一条证据，发版说明能对上 | 直接 main |

判档口诀：**一句话说不出"用户会看到什么变化"，就是 S。**

## 产物

```
docs/spec/<id>.md      需求单（PM 写，CTO 补方案段）
docs/qa/<id>.md        测试单（QA 写）
docs/retro/<version>.md 复盘（发版后写）
docs/NOW.md            一页看板：在做什么、卡在哪、下一步
```

`<id>` 用 `版本号-短名`，例如 `26.5.0-boot-intro`。三张单子都从 `TEMPLATE.md` 起手：

```bash
tools/spec.sh new L 26.5.0-boot-intro "开机字标动画"
```

## 节奏

- **开工**：读 `docs/NOW.md`（一页）→ 昨天的 `retro`（如果有）→ 昨天的 memory 日志。一页看板优先，别一上来读 300 行日志。
- **做完一个需求**：更新 NOW.md → 发版（M/L 档）→ 24 小时内写复盘。
- **每周**：把复盘里**重复出现两次以上**的根因升级成流程改动，直接改这个文件。流程本身也要复盘。

## 复盘怎么写

不是流水账。五段，控制在半页：

1. **事实**：计划做什么、实际做了什么、差在哪（带数字：几次编译、几轮返工、多久）
2. **运气**：哪些结论是碰对的，不是推对的（这类最危险）
3. **可复用**：这次摸索出的方法，下次直接照做
4. **改进项**：每条必须指定"落到哪里"——脚本、门禁、还是文档。没有归属的改进项等于没写
5. **漏网**：QA 没抓到、发版后才发现的，单独列。连续两次同类漏网，就要动门禁

## 违规怎么办

流程是给自己用的，不是拿来审判的。自己发现违规 → 补单子，在复盘里写一句"跳过了 G1"；QA 发现 → 进复盘的「漏网」段。**连着两次同类问题，改流程，不改人。**
